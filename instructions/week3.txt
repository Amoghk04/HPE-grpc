# Guide to Setting Up and Using the gRPC and HTTPS Server

## Prerequisites
- Ubuntu Linux (tested on Ubuntu 22.04)
- C++ compiler (GCC 13.3.0 or later)
- CMake (3.10 or later)
- OpenSSL
- gRPC and Protocol Buffers installed from source
- Abseil library

## Directory Structure
```
HPE-grpc/grpc/
├── build/           # Build directory
├── certs/           # SSL certificates
│   ├── server.crt   # Server certificate
│   └── server.key   # Server private key
├── uploads/         # Directory for uploaded files
├── downloads/       # Directory for downloaded files
├── service.proto    # Protocol buffer definitions
├── server.cpp       # Server implementation
├── client.cpp       # Client implementation
└── CMakeLists.txt   # CMake configuration
```

## Step-by-Step Setup

1. First, deactivate conda if it's active:
   ```bash
   conda deactivate
   ```

2. Create necessary directories:
   ```bash
   cd ~/new/HPE-grpc/grpc
   mkdir -p certs uploads downloads
   ```

3. Generate SSL certificates:
   ```bash
   openssl req -x509 -newkey rsa:4096 -keyout certs/server.key -out certs/server.crt -days 365 -nodes -subj "/CN=localhost"
   ```

4. Build the project:
   ```bash
   rm -rf build
   mkdir -p build
   cd build
   cmake ..
   make -j$(nproc)
   ```

5. Copy SSL certificates to build directory:
   ```bash
   mkdir -p certs
   cp ../certs/server.* certs/
   ```

## Running the Server

1. Start the server:
   ```bash
   ./server
   ```
   The server will start two services:
   - HTTPS server on port 8443
   - gRPC server on port 50051 (with SSL)

2. Verify server is running:
   ```bash
   curl -k https://localhost:8443/hi
   ```
   Expected output: "Hello HI from the HTTPS server!"

## Available Services

### HTTPS Endpoints (Port 8443)
1. Basic Endpoints:
   - GET /hi - Simple hello message
   - GET / - Root endpoint
   - POST /echo - Echoes back the request body

2. API Endpoints:
   - POST /api/hello - Bridges to gRPC Greeter service
   - GET /status - Server status information

3. Data Management:
   - GET /data - List all stored data
   - GET /data/{id} - Get data by ID
   - POST /data - Store new data
   - PUT /update/{id} - Update existing data

4. File Operations:
   - POST /upload - Upload a file
   - GET /download/{filename} - Download a file

### gRPC Services (Port 50051)
1. Greeter Service:
   - SayHello - Simple greeting
   - SayHelloAgain - Repeated greeting

2. Network Configuration Service:
   - ConfigureIP - Configure network interface (supports DHCP and static IP)

3. File Service:
   - UploadFile - Upload files to server
   - DownloadFile - Download files from server

## Running the Client

1. Create a test file:
   ```bash
   echo "This is a test file content" > test.txt
   ```

2. Run the client:
   ```bash
   ./client
   ```
   The client will:
   - Test gRPC calls (Greeter, Network Config, File operations)
   - Test HTTPS calls (GET, POST, file upload/download)

## Security Features

1. HTTPS Server (Port 8443):
   - Uses TLSv1.3
   - RSA 4096-bit encryption
   - Self-signed certificate (for development)

2. gRPC Server (Port 50051):
   - SSL/TLS encryption
   - Mutual authentication support
   - Secure channel communication

## Troubleshooting

1. If server fails to start:
   - Check if SSL certificates exist in certs directory
   - Ensure ports 8443 and 50051 are available
   - Check server logs for error messages

2. If client fails to connect:
   - Verify server is running
   - Check SSL certificates are properly copied
   - Ensure correct ports are being used

3. File operations issues:
   - Check uploads and downloads directories exist
   - Verify file permissions
   - Check available disk space

## Notes
- The server uses self-signed certificates for development
- For production, use certificates from a trusted CA
- Both gRPC and HTTPS servers run with SSL/TLS encryption
- File operations are thread-safe with mutex protection
- The server supports both synchronous and asynchronous operations
